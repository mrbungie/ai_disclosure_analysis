Two Harnesses, One Optimization Cycle

The extraction pipeline contains two rule-based harnesses — keyword machinery that stands in for an LLM at corpus scale. Each is fit by the same optimization cycle (sample → LLM judge → dev-only search → freeze → single holdout look → write back), instantiated once per harness. This is the meta-harness framing: the cycle is the reusable object; the harnesses are its two application sites.

The optimization cycle (generic)

One pass = one labeled batch. Dev is spent freely by the search; the holdout is read exactly once, and a disappointing result forces a fresh batch — never a re-roll.

Where the cycle attaches to the pipeline

The corpus pipeline runs left to right. Each colored loop is one instantiation of the cycle above, pulling samples out of the pipeline and writing a frozen keyword artifact back into it.
